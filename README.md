3D 상점 환경에서 상품 구매, 진열, 고객 응대, 계산, 하루 정산, 저장/불러오기를 구현한 1인칭 상점 운영 시뮬레이터입니다.  
플레이어는 상점 주인이 되어 상품을 구매하고 진열대에 배치하며, 고객이 선택한 상품을 계산합니다.  
하루가 종료되면 아이템 구매에 사용한 비용과 판매 금액을 정산하고, 저장/불러오기 기능을 통해 상태를 이어갈 수 있습니다.

## 핵심 구현

### 1. 고객 AI 시스템

고객은 상점에 입장한 뒤 진열대의 상품을 탐색하고, 상품을 선택한 후 계산대로 이동합니다.
계산이 완료되면 상점을 퇴장합니다.
대기열 이탈 또는 미결제 상황에서는 보유한 상품을 반납함에 반납한 뒤 퇴장하도록 했습니다.

```text
상점 입장
→ 상품 선택
→ 계산대 이동
→ 계산 완료
→ 퇴장
```

예외 상황에서는 고객이 들고 있던 상품을 잃어버리지 않도록 반납함 시스템과 연결

```text
미결제 / 대기열 이탈
→ 보유 상품 반납함으로 반납
→ 고객 퇴장
```

---

### 2. 상품 구매 및 진열 시스템

플레이어가 상품을 구매하면 지정된 구역에 상품이 생성됩니다.  
플레이어는 생성된 상품과 상호작용해 손에 들 수 있으며, 해당 상품을 진열대에 가져가 배치할 수 있습니다.

```text
상품 구매
→ 지정 구역에 상품 생성
→ 상호작용을 통해 상품 픽업
→ 진열대와 상호작용
→ 진열대 슬롯에 상품 배치
```
상품 구매, 픽업, 진열을 분리하여 구매 UI와 실제 월드 오브젝트 상호작용이 자연스럽게 이어지도록 구현했습니다.
또한 플레이어가 이미 상품을 들고 있는 상태에서는 다른 상품을 들 수 없도록 제한하여 아이템 참조가 꼬이거나 기존 아이템이 사라지는 상황을 방지했습니다.

---

### 3. 계산대 및 매출 처리

고객은 상품을 선택한 뒤 계산대로 이동하기 전에 계산 대기열에 빈자리가 있는지 확인합니다.
대기열에 진입할 수 있는 경우 계산대로 이동하며, 계산 처리가 완료되면 고객이 가진 상품 가격을 합산하여 매출에 반영합니다.

```text
상품 선택 완료
→ 계산 대기열 진입 가능 여부 확인
→ 계산대로 이동
→ 계산 처리
→ 상품 가격 합산
→ 매출 반영
→ 고객 퇴장
```
이를 통해 고객 행동, 계산대 처리, 하루 정산 시스템이 하나의 흐름으로 연결되도록 구현했습니다.

---

### 4. 반납함 시스템

고객이 계산하지 않고 퇴장하거나 대기열에서 이탈하는 경우, 고객이 들고 있던 상품은 반납함에 저장됩니다.
플레이어는 반납함과 상호작용하여 상품을 하나씩 다시 가져올 수 있습니다.

```text
고객 이탈
→ 고객 보유 상품 확인
→ 반납함에 상품 저장
→ 플레이어가 하나씩 회수
```

반납함에서 상품을 가져올 때는 플레이어가 이미 상품을 들고 있는지 먼저 검사한 뒤, 실제로 들기에 성공했을 때만 반납함 목록에서 제거하도록 처리했습니다.
이를 통해 아이템을 들 수 없는 상태에서 반납함 상품이 사라지는 문제를 방지했습니다.

---

### 5. 하루 정산 시스템

하루가 종료되면 판매 매출, 상품 구매 비용, 유지 비용을 계산하여 결과 화면에 표시합니다.
정산이 끝난 뒤 다음 날로 넘어가며, 현재 상태를 저장할 수 있도록 구성했습니다.

```text
하루 종료
→ 판매 매출 계산
→ 구매 비용 / 유지 비용 계산
→ 결과 화면 표시
→ 진행 상태 저장
→ 다음 날 진행
```

정산 시스템은 단순히 결과 UI를 표시하는 것에서 끝나지 않고, 저장/불러오기 시스템과 연결되어 플레이어의 진행 상태가 유지되도록 구현했습니다.

---

### 6. 저장 및 불러오기 시스템

게임 진행 상태는 JSON 형식으로 저장합니다.  
SaveManager는 저장 파일 입출력을 담당하고, GameManager는 현재 씬의 상태를 저장 데이터로 변환하거나 불러온 데이터를 실제 게임 오브젝트에 적용합니다.

```text
현재 게임 상태
→ SaveData 생성
→ JSON 파일 저장
→ 이어하기 시 JSON 불러오기
→ 게임 상태 복원
```

저장 대상은 다음과 같습니다.

- 날짜
- 보유 금액
- 누적 매출
- 진열대 상품 상태
- 바닥 재고 아이템
- 플레이어가 들고 있는 아이템
- 반납함 아이템

저장 대상이 씬 오브젝트에 분산되어 있기 때문에, 각 시스템에서 저장 데이터를 생성하고 GameManager가 이를 모아 하나의 SaveData로 구성하도록 구현했습니다.

---

### 7. 오디오 및 옵션 시스템

BGM과 효과음은 AudioManager에서 관리합니다.  
메인 메뉴와 인게임에서 같은 음량 설정을 공유하며, BGM/SFX 음량은 PlayrPrefs를 통해 저장합니다.

```text
옵션 슬라이더 조절
→ AudioManager 음량 변경
→ PlayerPrefs 저장
→ 다음 실행 시 음량 복원
```

## 개발 중 해결한 문제

### 1. 반납함 아이템 회수 시 아이템이 사라지는 문제

반납함에서 아이템을 가져올 때, 플레이어가 이미 아이템을 들고 있는 상태에서도 반납함 목록에서 아이템이 먼저 제거되는 문제가 있었습니다.

#### 원인
아이템을 실제로 들 수 있는지 확인하기 전에 반납함 데이터에서 아이템을 먼저 제거하는 순서가 문제였습니다.

```text
기존 흐름

반납함 아이템 가져오기 시도
→ TakeItem() 내부에서 반납함 목록의 첫 번째 아이템 제거
→ 플레이어 아이템 보유 여부 확인
→ 이미 아이템을 들고 있어 픽업 실패
→ 이미 제거된 아이템을 복구하지 못해 아이템 손실 발생
```

#### 해결
반납함의 아이템을 먼저 확인만 하고, 플레이어가 아이템을 성공적으로 들었을 때만 반납함 목록에서 제거하도록 순서를 변경했습니다.

```text
수정 후 흐름

반납함 첫 번째 아이템 확인
→ 플레이어 아이템 보유 여부 확인
→ 아이템 픽업 성공
→ 반납함 목록에서 첫 번째 아이템 제거
```

이를 통해 플레이어가 아이템을 들 수 없는 상태에서는 반납함 데이터가 변경되지 않도록 처리했습니다.

---

### 2. UI 버튼 클릭이 동작하지 않는 문제

일시정지 메뉴의 옵션 버튼이 클릭되지 않는 문제가 발생했습니다.  
다른 버튼은 정상적으로 동작했기 때문에 버튼 이벤트 연결 문제가 아니라 UI Raycast 충돌 가능성을 확인했습니다.

#### 원인
클릭 대상이 아닌 텍스트 UI가 버튼 위를 덮고 있었고, 해당 Text 컴포넌트의 Raycast Target이 켜져 있어 버튼 클릭을 가로막고 있었습니다.

```text
텍스트 UI가 버튼 위에 위치
→ Text Raycast Target 확성화
→ 클릭 이벤트가 버튼까지 전달되지 않음
```

#### 해결
클릭 대상이 아닌 텍스트와 장식용 UI의 Raycast Target을 비활성화했습니다.

```test
장식용 Text / Image
→ Raycast Target 비활성화

Button / Slider
→ Raycast Target 유지
```

이후 버튼 클릭 이벤트가 정상적으로 동작하는 것을 확인했습니다.

고객 AI가 상품을 선택하고 계산대로 이동하는 흐름, 미결제 상품 혹은 예외 상황에서 퇴장 시 반납함에 아이템을 반납시키고 이동하는 흐름, JSON 기반 저장/ 불러오기를 통해 씬 상태를 복원하는 구조를 구현하면서 각 시스템 간 데이터 흐름을 설계하는 것이 중요하다는 점을 배웠습니다.

향후에는 상품 추가와 고객 행동을 더 다양화하고, 상점 성장 요소와 UI연출을 보강하여 실제 게임 플레이의 완성도를 높이고자 합니다.
